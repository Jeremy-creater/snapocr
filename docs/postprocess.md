# 文本后处理（F2）

`snapocr.postprocess` 把 OCR 引擎返回的 `OcrResult` 变成最终放进剪贴板的文本。入口是 `postprocess(result, options)`，开关是 `PostprocessOptions`，规则顺序固定为 `RULE_ORDER`。这个包只依赖标准库和 `snapocr.engines.types`，不需要 OCR 模型、翻译服务或 GUI。

## 规则顺序

规则按下面的顺序执行（与 `RULE_ORDER` 一致）：

1. `layout`（F2-0，不能关闭）：把文本块按阅读顺序分成行。竖直方向重叠足够多的块算同一行，同一行内按从左到右拼接；两侧任一字符是汉字或全角标点时不加空格，否则加一个空格。行与行之间的空隙明显大于行高时，记为段落间隔，输出时变成一个空行。这条规则负责把块变成文本，没有它就没有输出，所以没有开关。整个文本区域的左右边界 `(最左, 最右)` 也在这一步算一次，后面的规则共用。
2. `paragraphs`（F2-3，开关 `paragraphs`）：把被自动折行的行合并回一个段落。只有同时满足这几条才合并：两行之间没有段落间隔；上一行不以句末标点结尾；上一行是满行（右边界接近区域右界）；下一行不是列表项。关掉后每个识别行单独一行，但段落间隔的空行仍然保留。
3. `spacing`（F2-1，开关 `spacing`）：在直接相邻的汉字和英文字母或数字之间加一个空格，例如 `使用Python3截图` 变成 `使用 Python3 截图`。网址、路径、邮箱和反引号里的内容不改。
4. `punctuation`（F2-2，开关 `punctuation`）：中文语境里的半角标点 `,;:?!.` 转成全角 `，；：？！。`，并删掉转换后标点两侧的空格。数字里的标点（`3.14`、`1,000`）、省略号、`文件.txt`、行首列表编号 `1. ` 和受保护片段里的标点不转。
5. `finalize`（不能关闭）：去掉每行行尾的空白，去掉开头和结尾的空行，用 LF（`\n`）拼接，末尾不带换行。行首空白和中间的空行保留。

## 为什么是这个顺序

- 段落合并放在加空格前面：两行合并后，接缝处可能正好是汉字和英文相邻（比如上一行以 `snapocr` 结尾、下一行以 `截图` 开头）。先合并、再加空格，接缝处也能得到空格；反过来，接缝就会被漏掉。
- 加空格放在标点转换前面：F2-2 判断语境时会跳过空格，转换后又会删掉标点两侧的空格。所以先加的空格不会影响标点判断，多出来的空格也会被标点规则清理掉，两条规则串起来仍然幂等。
- 版面分析不能关：它是把块变成文本的唯一步骤，其他规则都作用在它的输出上。
- 收尾总在最后：前面的规则可能在行尾留下空白或在首尾留下空行，统一在最后清理。

## 替换表

`replacements`（F2-6，常见误识别的替换表）在 M1 不做，推迟到 M2，和 F9（配置文件读取）一起实现。它不在 `RULE_ORDER` 和 `PostprocessOptions` 里。

## 保证

- 对任何开关组合，空结果（或只有空白块）都输出 `""`。
- 输出与输入块的顺序无关。
- 除空白和半角/全角标点的对应以外，输出的字符与识别出的字符完全一致，不增不减。
- 文本规则链（`spacing`、`punctuation`）对自己的输出再跑一遍不会再变化。
