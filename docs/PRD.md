## 1. 背景

日常的截图、OCR、翻译分散在几个工具里（截图软件、Umi-OCR、翻译软件），切换成本高；OCR 结果还要手动清理空格、标点、断行；翻译默认走云端。

snapocr 是一个**独立运行**、托盘常驻的 GUI 小工具：**一个热键完成一件事，结果直接进剪贴板**。OCR 引擎内置在 snapocr 里（RapidOCR，PP-OCR 模型），翻译用本机本地模型。装好 snapocr 后，不再需要 Umi-OCR。

## 2. 目标与非目标

**目标**
- G1：全局热键分别完成"截图 → 剪贴板""截图 → OCR 文本 → 剪贴板""截图 → 译文 → 剪贴板"。
- G2：只运行 snapocr 一个软件（翻译时另需本地模型服务）；全程本地离线。
- G3：后处理规则、翻译模型、热键可配置；核心逻辑可在无 GUI 环境下测试。

**非目标（本阶段不做）**
- 不自研 OCR 模型（使用 PP-OCR 现成模型）。
- 不 fork 或修改 Umi-OCR 源码。
- 不做截图标注、贴图（钉在屏幕上）、录屏、长截图。
- 默认不调用云端大模型；以后若要接云端，必须显式开启。
- 只支持 Windows 11，不做跨平台。
- 不做安装包 / 打包分发（先用 venv 启动）。

## 4. 产品形态与交互

- 启动后只在系统托盘常驻，没有主窗口。托盘菜单：截图 / OCR / 翻译 / 上次结果（与热键等价）、打开配置文件、退出。
- 默认热键（两键组合，可在配置里改）：

  | 热键 | 动作 |
  |---|---|
  | `Alt+1` | 截图 → 剪贴板 |
  | `Alt+2` | 截图 OCR → 剪贴板 |
  | `Alt+3` | 截图翻译 → 浮窗 + 剪贴板 |
  | `Alt+4` | 打开"上次结果"窗口 |

- 按下截图类热键 → 冻结当前所有屏幕 → 框选区域 → 松开鼠标即执行对应动作。Esc 或右键取消。
- 截图和 OCR 的结果用托盘通知提示；翻译结果用浮窗显示。

## 5. 架构概览

```
GUI 外壳 (snapocr.gui, PySide6) ── 托盘 / 热键 / 框选遮罩 / 浮窗 / 上次结果窗口 / 剪贴板
        │ 只做界面和 I/O，不含业务规则
        ▼
动作编排 (snapocr.actions) ── capture / ocr / translate 三条流程 + 上次结果（内存）
        │
        ├── OCR 引擎适配层 (snapocr.engines)   → RapidOCR（进程内，onnxruntime，本地模型文件）
        ├── 文本后处理 (snapocr.postprocess)    纯逻辑：版面整理、空格、标点、段落
        └── 翻译适配层 (snapocr.translators)    → 本地模型 OpenAI 兼容接口（默认 Ollama 127.0.0.1:11434）
```

**新增运行时依赖及理由**
- `rapidocr` + `onnxruntime`：内置 OCR 引擎。使用 PaddleOCR 的 PP-OCR 模型（与 Umi-OCR 同一模型家族，中英混排效果好），Apache-2.0，pip 即装，支持 Python 3.12，在进程内调用，不需要外部 exe 或服务。
- `PySide6`：一个依赖同时覆盖托盘、多屏高 DPI 框选遮罩、剪贴板图片、浮窗，是 Qt 官方 LGPL 绑定。代价是体积大（约 200 MB，只装在 venv 里）。
- 全局热键用 Win32 `RegisterHotKey`（`ctypes`，标准库），不引入第三方热键库。
- HTTP（翻译）用标准库 `http.client`，不引入 requests/httpx。不用 `urllib.request`：它会读取系统代理（环境变量、Windows 注册表）并自动跟随 3xx 跳转，可能把请求带出 127.0.0.1（2026-10-25 定，F4 D3）。

**翻译模型服务**：snapocr 不内置大模型推理，通过 OpenAI 兼容接口调用本机的 Ollama（或 LM Studio、llama.cpp server，改配置即可）。原因是 7B 模型的 GPU 推理放在独立服务里更稳，也能与其他工具共用。

## 7. 功能需求与验收标准

验收标准写成可测试的形式，是 TDD 计划的直接输入。

### F1 OCR 引擎（M1）

| ID | 验收标准 |
|---|---|
| F1-1 | 给定图片字节（PNG），返回引擎无关的结构化结果：文本块列表（文本、四点坐标、置信度）。业务代码只依赖这个结构，不依赖 RapidOCR 的类型。 |
| F1-2 | 图中无文字时返回空结果，不报错。 |
| F1-3 | 输入为空、不是图片或图片损坏时，抛出明确异常，信息说明原因。 |
| F1-4 | 运行时不联网：模型文件在本地；模型缺失或加载失败时抛出明确异常，给出模型路径和修复方法。 |
| F1-5 | 引擎首次使用时加载，之后复用同一实例；加载失败不会让程序崩溃。 |
| F1-6 | 最低置信度可配置（默认 0.5【待确认】），低于阈值的块被过滤。 |
| F1-7 | 对固定的样例图片（`tests/fixtures/`，中文、英文、中英混排各一张），识别文本与人工校对文本一致（允许的字符错误率在计划中确定）。 |

### F2 文本后处理（M1）

| ID | 验收标准 |
|---|---|
| F2-0 | 版面整理：按坐标把文本块排成阅读顺序（从上到下、从左到右），同一行的块合并成一行；行间竖直间隔明显大于正常行距时（初值 1.5 倍行高中位数）标记为段落间隔。阈值是计划内常数，由 F2 计划 WI-8 用样例图校准。 |
| F2-1 | 中文与英文 / 数字之间补一个半角空格（"使用Python3" → "使用 Python3"）。 |
| F2-2 | 中文语境下的半角标点转全角（`,` → `，`），英文句子、URL、代码、数字里的标点不变。 |
| F2-3 | 把被 OCR 断开的同一段落的行合并；空行和列表项保持分段。合并条件（2026-10-25 定，方案 B）：相邻两行**同时满足**——两行之间没有段落间隔、上一行不以句末标点结尾、上一行是满行（右边缘达到区域宽度的约 0.85 倍）、下一行不是列表项。默认开启，可关闭；误合并可从 F10 原文找回。 |
| F2-4 | 每条规则可单独开关；规则链的顺序固定，并有文档说明。 |
| F2-5 | 性质：所有文本规则**幂等**（处理两次 = 处理一次）；空字符串输入输出为空字符串。 |
| F2-6 | 自定义替换表（常见误识别，如 `l` 和 `1`、`O` 和 `0`）从配置加载。**放到 M2，与 F9 配置一起做**（2026-10-25 定：读配置属于 F9；没有评测集前无法确定替换项；无约束的替换表会破坏 F2-5 幂等）。 |

### F4 翻译客户端（M1）

| ID | 验收标准 |
|---|---|
| F4-1 | 方向自动判断：`汉字数 / (汉字数 + ASCII 字母数) ≥ 阈值`（默认 0.3，按比例比较）时译为英文，否则译为中文；整段只判一个方向。既没有汉字也没有 ASCII 字母（如只有数字、符号）时不调用模型，原文原样返回并标记为已跳过。配置可固定目标语言，覆盖自动判断。 |
| F4-2 | 请求走 OpenAI 兼容接口 `POST {base_url}/v1/chat/completions`，`stream=false`，请求体包含配置的模型名、提示词模板渲染后的消息和采样参数。 |
| F4-3 | 输出清洗：去掉 `<think>…</think>` 块（含未配对标签的残留）和首尾空白；清洗后为空视为失败。`finish_reason` 为 `length`（输出被截断）也视为失败，不返回半截译文。 |
| F4-4 | 输入为空或全是空白时，不调用模型，直接返回空结果。 |
| F4-5 | 服务不可达、超时、连接异常、模型不存在、HTTP 错误状态、返回格式不对、输出为空、输出被截断、输入过长，都抛出明确异常（带错误类别和修复提示），信息中包含 `base_url` 和模型名，不包含原文、译文或响应体内容。失败不自动重试。 |
| F4-6 | `base_url`、模型名、超时、提示词模板、采样参数可配置。默认 `http://127.0.0.1:11434`，模型 `hy-mt2:7b`（由 `docs/hy-mt2-7b.Modelfile` 导入），超时 60 s；默认提示词用模型卡格式："把下面的文本翻译成{target_language}，不要额外解释。\n\n{source_text}"（目标语言名为"英语"/"中文"，两个方向同一模板，只发一条 user 消息；占位符按字面量替换，原文最后代入）。默认采样参数 `temperature 0.7`、`top_p 0.8`（与 Modelfile 一致），只允许 OpenAI 兼容字段。`base_url` 只接受 `http://127.0.0.1:<端口>`（必须写端口、不带路径；`localhost`、`::1`、其他 127.x 写法一律拒绝），不提供允许外网的开关。超时是 socket 级（连接和每次读），非流式下等同总时长。输入超过 `max_input_chars`（默认 4000 码点）时报错，不截断、不调用模型。 |

## 8. 非功能需求

| 项 | 要求 |
|---|---|
| 离线 | 只访问 `127.0.0.1`（本地模型服务），不发起任何外网请求；OCR 模型文件在本地。 |
| 延迟 | 热键到遮罩出现 < 300 ms；OCR 从松开鼠标到剪贴板就绪 < 2 s（引擎已加载，1080p 满屏密排文字，CPU；原目标 1.5 s，2026-10-25 按实测由 Jeremy 改为 2 s，M2 用真实截图复测）；翻译 200 字以内 < 5 s（模型已加载，RTX 5080）【待确认】。<br>**实测（2026-10-25，WI-10）**：Intel Core Ultra 9 285K（24 核），onnxruntime 1.31.0 CPU，默认线程设置；1920×1080 密排 12 行中英文，加载 0.46 s，首次 2.54 s，预热后 5 次中位数 1.76 s（1.70–1.85 s），未达原 1.5 s 目标，满足新目标 2 s。<br>**翻译实测（2026-10-26，F4 WI-9）**：Ollama 0.40.11，hy-mt2:7b（Q6_K），RTX 5080；164 字中文段落译英文，模型已加载，预热后 5 次中位数 1.22 s（1.21–1.23 s），满足 5 s 目标（目标值仍待 Jeremy 确认）。冷启动见 §10。 |
| 隐私 | 不持久化截图和全文（"上次结果"只在内存），debug 模式除外；日志只写到 `D:\DevLocal\runtime\snapocr`。 |
| 资源 | 常驻内存 < 300 MB（含 OCR 模型，不含翻译模型服务）【待确认，引擎加载后实测】。 |
| 可测性 | 纯逻辑覆盖率只升不降（tdd-guardian `no-decrease`）；GUI 层保持薄，只做界面和 I/O。 |

## 9. 质量评估

- OCR 评测集：`tests/fixtures/eval/` 放 30–50 张真实场景的脱敏截图，附人工校对文本。指标是字符错误率（CER）；后处理不能让 CER 变差。
- 翻译评测集：20 段左右的中英双向样例，附参考译文，人工打分，用于比较模型和提示词。
- 【待确认】评测集截图和样例由 Jeremy 提供。

## 10. 风险

| 风险 | 应对 |
|---|---|
| RapidOCR 首次运行需要下载模型，违反离线要求 | 安装时一次性准备好模型文件，运行时只读本地路径；F1-4 用测试钉住"不联网" |
| RapidOCR 识别效果不如 Umi 现在的效果 | F1-7 样例对比 + 评测集；适配层隔离，可换 PaddleOCR 或 VLM |
| 标点 / 空格规则误伤代码和 URL | 用性质测试和反例覆盖；S4 代码模式单独处理 |
| 多屏不同缩放下截图错位 | 坐标换算抽成纯逻辑并重点测试；真实多屏组合手工验收 |
| `Alt+数字` 与其他软件冲突 | 可配置 + 注册失败明确通知（F5-3） |
| HY-MT2 在 Ollama 中无法加载（架构 `hunyuan-dense`、模板需手写） | 先实测导入；不行就改用 LM Studio 或 llama.cpp server，接口相同，只改配置 |
