# snapocr PRD

> 状态：**草稿 v0.1**（2026-10-25）。标 `【待确认】` 的条目需要 Jeremy 决定后才能进入 TDD 计划。

## 1. 背景

Umi-OCR 已能离线做截图 OCR，但输出是"识别结果"，不是"我要的文本"。日常还需要手动清理标点、空格、断行，再粘贴到别处（Obsidian、Claude、翻译）。snapocr 在 Umi-OCR 之上加一层可定制的后处理和输出编排。

## 2. 目标与非目标

**目标**
- G1：一个热键 / 命令，拿到"可直接用"的文本。
- G2：后处理规则可配置、可测试、可扩展。
- G3：输出可以接到不同目的地（剪贴板、文件、LLM）。

**非目标（本阶段不做）**
- 不自研 OCR 模型，不修改 Umi-OCR。
- 不做截图标注、贴图等功能（Snipaste/PixPin 的领域）。
- 不做 GUI 设置界面；配置用文件。
- 不做打包分发。

## 4. 里程碑

### M1：核心管线（无 GUI，纯 CLI）

- **F1 Umi 客户端**：调用 `POST /api/ocr`，返回结构化结果（文本块、坐标、置信度）。
- **F2 文本后处理**：可组合的规则链。
- **F3 CLI**：`python -m snapocr <image-file>` 和 `python -m snapocr --clipboard`，结果输出到 stdout，或用 `--copy` 写入剪贴板。

## 5. 功能需求与验收标准（M1）

验收标准写成可测试的形式，是 TDD 计划的直接输入。

### F1 Umi 客户端

| ID | 验收标准 |
|---|---|
| F1-1 | 给定 PNG 字节，发出的请求体包含正确的 base64 和合并后的 options。 |
| F1-2 | Umi 返回 `code=100` 时，解析出文本块列表（文本、四点坐标、置信度），顺序与返回一致。 |
| F1-3 | Umi 返回 `code=101`（图中无文字）时，返回空结果，不报错。 |
| F1-4 | 其他 code，或无法解析的 JSON，抛出带 code 和原始信息的明确异常。 |
| F1-5 | 连接被拒绝 / 超时，抛出"Umi-OCR 未运行或端口不对"的明确异常，并给出端口。 |
| F1-6 | 主机、端口、超时、默认 options 可配置；默认值为 `127.0.0.1:1224`。 |

### F2 文本后处理

| ID | 验收标准 |
|---|---|
| F2-1 | 中文与英文 / 数字之间补一个半角空格（"使用Python3" → "使用 Python3"）。 |
| F2-2 | 中文语境下的半角标点转全角（`,` → `，`），英文句子、URL、代码、数字里的标点不变。 |
| F2-3 | 把被 OCR 断开的同一段落的行合并；空行和列表项保持分段。 |
| F2-4 | 每条规则可单独开关；规则链的顺序固定，并有文档说明。 |
| F2-5 | 性质：所有规则**幂等**（处理两次 = 处理一次）；空字符串输入输出为空字符串。 |
| F2-6 | 自定义替换表（常见误识别，如 `l` 和 `1`、`O` 和 `0`）从配置加载。【待确认：是否 M1 就要】 |

### F3 CLI

| ID | 验收标准 |
|---|---|
| F3-1 | 文件不存在 / 不是图片时，退出码非 0，并输出可读的错误信息。 |
| F3-2 | 剪贴板里没有图片时，退出码非 0，并输出提示。 |
| F3-3 | `--raw` 跳过后处理；`--copy` 把结果写入剪贴板。 |

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 离线 | 默认全程离线；联网能力（S4 云端 LLM）必须显式开启。 |
| 延迟 | Umi 已运行时，从命令执行到结果输出 < 1.5 s（1080p 截图）。 |
| 隐私 | 不持久化截图和全文，debug 模式除外。 |
| 可测性 | 纯逻辑覆盖率只升不降（tdd-guardian `no-decrease`）。 |
